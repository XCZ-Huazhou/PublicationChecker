# PublicationChecker · 期刊分区查询

在网页上选中一个期刊名，**点右键 → 「查询期刊分区」**，结果就直接弹在当前页面上。

不用切标签页，不用打开查询网站，不用登录，不用联网。

内置 **23059 本期刊**的分区数据，装完就能查。整个扩展只有 2.3 MB，比一张手机照片还小。

| 能查到 | 版本 |
|--------|------|
| JCR 分区（含影响因子、学科四分位） | 2025 |
| 中科院分区（大类 / 小类 / Top） | 2025 升级版 |
| 新锐分区 | 2026 |

这份说明分两部分：**第一部分给普通用户**，讲插件能做什么、怎么装、怎么用；**第二部分给进阶用户**，讲怎么更换内置的期刊数据库。大多数人只需要看第一部分。

---

# 第一部分 · 普通用户

## 它解决什么麻烦

看文献列表、读审稿意见、挑投稿目标的时候，经常要核对某本期刊是几区、影响因子多少。平时的做法是：复制刊名 → 新开一个标签 → 打开分区查询网站 → 粘贴搜索 → 有的还要登录 → 查完再切回来。

这个扩展把这一串压成一步：**选中刊名，右键，看结果**。查完点一下页面别处就收起来，你原来在读的东西一点没动。

结果卡片只展示信息，**不放任何外链** —— 不会顺手把你带去别的网站。

## 怎么用

有两种用法，任选其一。

### 用法一：选中刊名 → 右键（最常用）

1. 在任意网页（http/https）上选中一个期刊名
2. 右键 →「查询期刊分区：xxx」
3. 结果弹在选中的地方，点页面别处即收起

![右键菜单里的「查询期刊分区：Conservation Biology」](docs/images/context-menu.png)

![网页上弹出的结果卡片，底部显示命中总数](docs/images/overlay.png)

### 用法二：点工具栏图标 → 直接输入

没有现成刊名、或者想直接搜？点浏览器工具栏上的扩展图标，在弹窗里输入期刊名或 ISSN 号，回车即查。

![工具栏弹窗：输入期刊名或 ISSN，结果直接列出](docs/images/popup.png)

## 结果卡片里有什么

- **刊名** + ISSN / E-ISSN
- **JCR 分区**、学科四分位，以及一个淡蓝色的**影响因子**标签
- **中科院分区**（大类 / 小类，Top 刊另有标记）
- **新锐分区**
- 收录情况（WOS 的 SCIE / ESCI 等）、是否综述刊、语种、出版机构、中文名

## 几个让查询更准的小技巧

- **尽量选中完整的英文刊名**（比如 `Applied Computing and Informatics`），这样最准。
- **只选中了一部分也没关系**，扩展会把相关的候选都列出来，你自己点一个。界面会告诉你一共命中多少条（比如「共 92 条匹配，按字母序显示前 8 条 —— 继续输入可缩小范围」），多打几个字母就能快速缩到你要的那本。
- **识别不准就直接改**：卡片顶部有个输入框，你选中的内容已经自动填进去了，**边打字边出结果**，按回车或点「查询」立即重查。
- 候选列表底部有「**继续查看**」，每点一次多显示 10 条。
- **也支持用 ISSN 查**，比刊名更精确。
- 选中文字本身不会被干扰（方便你正常复制粘贴），只有主动点右键菜单才会触发查询。

## 安装

> **Chrome / Edge 不能直接导入 ZIP。** 请先解压成一个文件夹，再加载那个文件夹。

到 [Releases](../../releases) 页面下载对应你浏览器的文件（两个文件名是固定的、不带版本号，以后发新版还是这两个名字）：

**Chrome / Edge** —— 下载 `PublicationChecker-chrome.zip`

1. 解压 zip，得到一个文件夹
2. 打开 `chrome://extensions`（Edge 是 `edge://extensions`）
3. 右上角开启「开发者模式」
4. 点「加载已解压的扩展程序」→ 选择刚解压出来的文件夹（要选到含 `manifest.json` 的那一层）

**Firefox / Zen** —— 下载 `PublicationChecker-firefox.xpi`

把 `.xpi` 拖进浏览器窗口，或在 `about:addons` 里选「从文件安装」。

### 360 极速等老版本浏览器

如果提示 **「requires version 109 or greater」** 或者装不上，需要换成仓库里的旧版清单：

1. 下载并解压 `PublicationChecker-chrome.zip`
2. 从[仓库](../../tree/main)里另外下载 `manifest-mv2.json` 和 `background-mv2.js`，放进解压出来的文件夹
3. 把文件夹里原来的 `manifest.json` 改名备份（比如 `manifest-mv3.json`），再把 `manifest-mv2.json` 改名为 `manifest.json`
4. 回扩展管理页加载这个文件夹

部分浏览器还需要在设置里允许「未知来源扩展」，或切换到极速内核。

## 常见问题

**要联网吗？要注册登录吗？**
都不用。23059 本期刊的数据随扩展一起装好，飞机上也能查。

**我查的东西会被传出去吗？**
不会。所有查询都在你自己电脑里完成，扩展不会把你的查询内容发给任何服务器。只有你主动点「检查更新」或「提 issue」时才会访问 GitHub。

**查询快吗？第一次会不会要等？**
即时的，第一次查也不用等。

**为什么有的期刊显示「未收录」？**
部分 ESCI 收录的期刊没有进入中科院分区表，属于数据本身的情况，不是查错了。

**数据是哪一年的？从哪来的？**
JCR 2025、中科院 2025 升级版、新锐 2026，来自社区整理项目 [hitfyd/ShowJCR](https://github.com/hitfyd/ShowJCR)。

**在 `chrome://` 这类页面上右键没弹出卡片？**
浏览器不允许在这类受限页面注入内容，扩展会自动改为打开一个完整的结果页。

**怎么升级到新版本？**
去 [Releases](../../releases) 下载最新的安装包，重新装一遍。这是唯一的办法 —— 浏览器不允许扩展替换自己的程序文件，所以**扩展里的「检查更新」按钮升级不了插件本身**，它只换期刊数据，详见第二部分。

# 第二部分 · 进阶用户：更换期刊数据库

## 先确认：你需要换库吗？

**大多数人不需要。** 扩展安装时已经自带完整的 23059 本期刊数据，装完即可用，不存在"要另外下载数据"这一步。

需要往下看的情况只有两种：

- 你**自己改了数据源**（比如去掉了中科院分区、只保留某个学科的期刊），想让扩展用你这份
- 新一年的分区表出来了，你想在**不重装扩展**的前提下先试试新数据

如果你只是想**升级到新版本插件**（要新功能、要修好的 bug），换库解决不了 —— 请直接重新下载安装包，见上面的「怎么升级到新版本」。

## 一个容易混淆的点：换库 ≠ 换插件

安装包下载下来是 2.3 MB，解压后约 2.4 MB，构成是这样的：

| | 体积 | 占比 | 换库时 |
|---|---|---|---|
| 期刊数据（`data/` 下的 3 个文件） | 2.27 MB | 95% | ✅ 被替换 |
| 插件程序（脚本、样式、页面、图标） | 0.12 MB | 5% | ❌ **原样不动** |

选项页的两个更新入口，做的都是「下载/读取一个安装包 → **只从里面取出那 3 个数据文件** → 存进浏览器存储 → 其余全部丢弃」。程序代码虽然在包里，但既不会被取出来，浏览器也不允许扩展覆盖自己的程序文件。

所以：**换库只换数据，不换插件。**

## 两条路线怎么选

| | 路线 A：在「关于」页导入 | 路线 B：改数据源后重新打包 |
|---|---|---|
| 要动代码吗 | 不用 | 要跑两条命令 |
| 要重装扩展吗 | 不用 | 要重新加载 |
| 网页右键浮层用新数据吗 | ❌ **不用**（仍用内置数据） | ✅ 用 |
| 工具栏弹窗 / 完整结果页 | ✅ 用新数据 | ✅ 用新数据 |
| 适合谁 | 想快速试一份数据、或只在弹窗里查的人 | 想真正换掉数据、所有入口都一致的人 |

**如果你在意网页右键浮层（也就是这个插件最主要的用法），只能走路线 B。**

## 路线 A：在「关于」页导入

入口：工具栏图标 →「**关于 PublicationChecker**」（或扩展详情页的「扩展程序选项」）。

| 来源 | 怎么选 |
|------|--------|
| **从本地更新** | Chrome / Edge：选解压后的扩展文件夹，扩展会整包读出其中的数据文件。Firefox / Zen：选 `.xpi` 包，扩展自己从包里解出来。也接受旧格式的单文件数据（`.json.gz` / `.json`） |
| **从 GitHub 更新** | 自动识别你的浏览器，从本仓库最新一次发布里取对应格式的安装包（Firefox 取 `.xpi`，Chrome 取 `.zip`），再从中解出数据。下载前会先显示检测到的版本号和当前扩展版本，你确认了才会下载 |

导入前会校验：格式不对、或条数少于 1000，会直接拒绝，**不会把你现有的库写坏**。

### ⚠️ 生效范围：网页右键浮层读不到

导入成功后，**只有扩展自己的页面能用上新数据**：

| 入口 | 导入后 |
|---|---|
| 工具栏弹窗 | ✅ 新数据 |
| 完整结果页 | ✅ 新数据 |
| 关于页 | ✅ 新数据 |
| **网页上右键弹出的浮层** | ❌ **仍是扩展内置的旧数据** |

原因是浏览器的安全规则：**每个网站的存储空间互相隔离**。扩展自己的页面属于"扩展"这个身份，能读到刚导入的数据；但网页上的浮层是注入到别人网站里运行的，你在 PubMed 上右键，那段代码就跑在 `pubmed.ncbi.nlm.nih.gov` 的地盘上，去读存储时浏览器给它的是 PubMed 的空间，扩展名下那份数据它看不见。

刷新页面也没用（身份不同这一点不会变）。这是浏览器的设计，不是 bug，绕不过去。

**结果就是：同一本期刊，从工具栏弹窗查和从网页右键查，可能给出不同答案。** 如果不希望出现这种不一致，请走路线 B。

### 想撤销导入、回到内置数据

**目前界面上没有"恢复内置库"的按钮**（清除的函数写好了，但还没接到按钮上）。要撤销只能：

- **卸载扩展再重新安装** —— 扩展名下的浏览器存储会被一并清掉，最省事
- 或者在扩展页面的开发者控制台里手动调用 `PublicationChecker.clearOverride()`

## 路线 B：改数据源后重新打包

这是**唯一能让所有入口都用上新数据**的方式。

1. 改 `raw/` 下的原始 CSV，或改 `tools/build_db.py`（例如去掉中科院分区：把 `load_cas(...)` 那行注释掉）
2. 重新生成数据库，再打包：

   ```bash
   python tools/build_db.py      # 输出统计里对应来源变成 0 即生效
   node build-chrome.js          # 或 node build-firefox.js
   ```

3. 重新加载扩展（`chrome://extensions` 里点刷新；Firefox 重装 xpi）

需要 Python 3（仅标准库，QGIS/ArcGIS 自带的也行）和 Node.js（只在打包时用）。

**注意：不要直接把仓库根目录加载成扩展。** 里面的原始数据（14 MB）和版本历史（14 MB）会被一起算进体积，扩展管理页会显示 30 MB 以上。请加载构建脚本产出的目录。
